# takulife

공식 서브컬처 이벤트 탐색과 기록을 연결하는 서비스

## Overview

- takulife는 서브컬처 오프라인 이벤트를 더 많이 모으기 위해 시작한 프로젝트가 아님
- 출발점은 정보 부족이 아님
- 출발점은 정보 분산으로 인한 사용자 피로도 증가
- 사용자는 여러 공식 채널을 반복 탐색
- 찾은 뒤에도 정보의 공식성 재검증
- 목표는 이 반복 과정에서 발생하는 탐색 비용과 검증 비용 감소

## Problem

- 서브컬처 오프라인 이벤트 정보는 이미 여러 채널에 존재
- 공식 홈페이지
- X
- 협업 카페 공지
- 팝업 스토어 공지
- 극장 특전 공지
- 굿즈 예약 판매 페이지

- 문제는 정보의 부재가 아님
- 문제는 정보의 분산
- 사용자는 관심 있는 작품의 이벤트를 보기 위해 여러 채널을 다시 탐색
- 찾은 뒤에도 이 정보가 실제 공식 정보인지 다시 검증
- 정보 탐색과 정보 검증이 매번 별도로 발생
- 이 과정이 누적될수록 사용자 피로도 증가

## Problem Definition

- 이 프로젝트는 문제를 이벤트 정보 부족으로 정의하지 않음
- 정보 분산으로 인해 사용자의 피로도가 누적되는 구조를 문제로 정의
- 더 구체적으로는 공식 정보를 다시 찾고 다시 검증해야 하는 반복 비용을 문제로 정의
- 따라서 핵심은 더 많은 이벤트 수집이 아님
- 핵심은 신뢰 가능한 탐색 흐름 설계
- 목표는 정보량 확대보다 탐색 비용과 검증 비용 감소

## Options Considered

### 1. Link Curation

- 이벤트 링크를 모아 목록으로 제공
- 빠르게 시작 가능
- 구현 비용이 낮음
- 원문 출처를 그대로 보여주기 쉬움

Trade-off

- 사용자가 다시 원문으로 이동
- 실제 탐색 비용 감소 폭이 작음
- 정보 구조화가 약함
- 검증 책임이 여전히 사용자에게 남음

### 2. Community-driven Submission

- 이벤트 데이터를 빠르게 늘릴 가능성 존재
- 참여형 구조 형성 가능
- 커뮤니티 확장성과 결합 가능

Trade-off

- 초기 품질 관리 부담 증가
- 신뢰도 관리 어려움
- 공식성 기준이 흐려질 가능성 존재
- 지금 정의한 핵심 문제와 정확히 맞지 않음
- 탐색 문제보다 운영 리스크가 먼저 커질 수 있음

### 3. Official URL + Admin Review + Publish

- 공식 URL을 기준으로 초안 생성
- 추출 결과는 후보로만 취급
- 관리자 검수 후 게시
- 공개 정보의 신뢰성 통제 가능
- 탐색 비용과 검증 비용을 함께 낮출 수 있음

Trade-off

- 단순 링크 모음보다 구현 비용 증가
- 완전 자동화보다 운영 단계 추가
- 초기에는 데이터 확장 속도보다 품질 통제가 우선

## Final Decision

- 최종 선택은 Official URL + Admin Review + Publish
- 이유는 명확
- 이 프로젝트의 핵심 문제는 수집량 부족이 아님
- 정보 분산으로 인한 사용자 피로도 증가
- 따라서 자동화보다 먼저 필요한 것은 운영 가능한 구조
- 사용자가 보는 정보는 추출 결과가 아니라 검수 결과여야 함
- MVP에서는 더 똑똑한 추출보다 더 신뢰 가능한 게시 흐름 우선

## How This Decision Shaped the Product

- 공개 이전 단계와 공개 이후 단계 분리
- draft와 published event 분리
- 추출값을 확정값이 아니라 후보값으로 취급
- 관리자 승인 전에는 공개하지 않음
- 동일 공식 URL 중복 게시 방지
- 공식 이미지 저장 대신 기본 썸네일 사용

- 제품 구조 자체가 문제 정의의 결과
- 단순 페이지 구현이 아니라 신뢰 가능한 정보 흐름 설계

## Current Scope

### Public

- 공개 이벤트 목록 페이지
- 공개 이벤트 상세 페이지
- 이벤트 목록 API
- 이벤트 상세 API
- 지역, 날짜, 카테고리, 키워드 기반 필터

### Admin / Ingestion

- 공식 URL 기반 draft 생성 API
- draft 목록 조회 API
- draft 상세 조회 API
- 제목, 날짜, 위치 후보 추출
- 관리자 승인 워크플로
- 관리자 반려 워크플로
- 승인된 draft를 published event로 전환
- 중복 URL 방지
- 안전하지 않은 URL 차단
- 운영자용 브루트포스 잠금 대응·배포 체크리스트: [docs/operations-runbook.md](docs/operations-runbook.md)

### Personal Archive

- 홈 화면 기준 탐색과 기록 흐름 연결
- 찜, 방문 예정, 방문 기록(사진 포함) 생성 및 조회 API
- 비공식 개인 항목(`PersonalEntry`) — 사용자가 직접 발견한 장소나 보유 굿즈를 본인만 보는 비공개 기록으로 등록
- 찜 / 방문 예정 / 방문 기록은 공식 이벤트 또는 비공식 개인 항목 중 하나를 대상으로 가질 수 있음 (subject 패턴)
- 나의 일정, 찜 목록, 저장한 행사에서 공식과 비공식을 함께 표시(직접 등록 마크 노출), 굿즈는 구매 기준 라벨 사용
- 방문 기록은 전용 **작성·수정 페이지**에서 관리 — 인스타그램식 다중 사진 미리보기·제거, 기록당 **최대 5장**(프론트·백엔드 모두 제한), 대표 사진은 첫 장
- 방문 타임라인은 **카테고리별(+비공식) 필터**, 카드 사진은 **캐러셀**로 미리보기
- 아카이브 상단 네비게이션은 **아코디언 메뉴**(저장한 행사·나의 일정·다녀온 기록 / 직접 등록 · 찜 목록), 찜·예정 등 상태 UI는 전 페이지 일관(예정=앰버, 완료=민트, 놓침=로즈)
- 비공식 개인 항목은 공개 카탈로그(`/events/`)로 절대 노출되지 않음

### Official Submission (공식 제보)

- 사용자가 비공식 개인 항목을 공식 URL과 함께 제보 가능
- 제보는 곧바로 공개되지 않음 — 기존 관리자 검수(draft) 파이프라인에 PENDING 초안으로 진입
- 관리자 승인 시에만 published event로 전환 (공개 신뢰 흐름을 그대로 유지)
- 제보 상태를 항목에 표시하고 중복 제보 차단

### Accounts / 인증

- 이메일 기반 계정 (django-allauth) — 회원가입 시 **이메일 인증 필수**, 비밀번호 재설정 지원, 이메일이 로그인 식별자
- Google 소셜 로그인 — 검증된 이메일이면 기존 계정과 **자동 연결** (Google 전용, 완전 신뢰 provider / OAuth 자격증명 설정 시 활성)
- 무차별 대입 방어 — 로그인 실패 rate limit + **django-axes IP 락아웃**(쿨오프), 가입·비밀번호 재설정 폭주 제한, 초과 시 한국어 안내 페이지

## What I Intentionally Did Not Build

- AI 기반 자동 추출
- 사용자 제보가 검수 없이 곧바로 공개되는 구조 (제보는 관리자 검수 파이프라인을 통해서만 공개)
- 커뮤니티 피드
- 댓글
- 메시지
- 결제
- 추천 시스템

Reason

- 현재 단계에서 중요한 것은 기능 수 확장이 아님
- 먼저 검수 가능한 이벤트 운영 흐름 확보
- 먼저 신뢰 가능한 공개 데이터 구조 확보
- 먼저 탐색 문제를 작게라도 정확히 해결
- 개인 비공식 기록은 허용하되, 공개 데이터는 끝까지 검수 결과만 유지(개인 항목과 공개 카탈로그를 명확히 분리)

## Tech Stack

- Django
- Django REST Framework
- django-allauth 기반 인증 (이메일 인증, 비밀번호 재설정, Google 소셜 로그인)
- django-axes 로그인 brute-force 락아웃
- SQLite 기반 로컬 개발 환경
- PostgreSQL 전환 고려 설계
- URL fetch + extraction workflow
- 서비스 레이어 분리
- pytest 기반 백엔드 로직 테스트 구성

## Key Takeaway

- takulife는 이벤트를 더 많이 수집하는 프로젝트가 아님
- 공식 서브컬처 이벤트를 더 낮은 비용으로 탐색하고 더 신뢰 가능한 방식으로 기록하기 위한 구조 설계
- 만들고 싶었던 것은 단순 목록 페이지가 아니라 탐색과 검증의 반복 비용을 줄이는 흐름
