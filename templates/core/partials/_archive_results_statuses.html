"삭제" 버튼은 data-remove-on-cancel 대신 data-reload-on-success를 쓴다 — 이 행은 라이브 검색이 통째로 교체하는 영역 안에 있어서, 삭제 진행 중에 검색 스왑이 겹치면 서버가 이미 지운 행이 새로 렌더돼 유령 행으로 남기 때문이다. .record-row-actions에는 data-status-error-container를 직접 붙인다 — 형제가 최대 3개(상태 버튼 2개 + 삭제)라 부모 요소로의 폴백에 기댈 수 없다. CTA 순서는 [기록 CTA] → [예정으로] → [삭제]를 유지해야 한다 — CSS margin-right:auto가 첫 자식에만 걸리기 때문이다. {% endcomment %}
