{% comment %} _account_settings_field.html — label(+*) + input + field error, wired for IC4 (id="{id}-error", aria-describedby only when this field has an error). Renders the manually instead of `{{ field }}`. NOT because Django can't do this — Django 5.2's BoundField already emits aria-invalid and aria-describedby on its own. It points them at *its* ids (`id_x_error`, `id_x_helptext`), and this partial renders its own error element as `id_x-error` and no help_text row at all, so `{{ field }}` here would emit references to elements that don't exist. Rendering manually is what keeps every reference resolvable. If you ever switch back to `{{ field }}`, match Django's id format and render help_text, or you reintroduce the dangling references. See docs/FE/auth-editorial.md A2. Preserves any attrs the form field's widget already sets (autocomplete, maxlength, ...) by echoing widget.attrs verbatim. Password inputs never echo back `field.value` — Django's own PasswordInput renders empty for the same reason (render_value=False); reproducing that manually here matters because this partial replaces `{{ field }}` entirely. Usage: {% include "core/partials/_account_settings_field.html" with field=form.email label="이메일" %} {% endcomment %}
