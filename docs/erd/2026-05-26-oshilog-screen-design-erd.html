OshiLog 화면 설계 기반 DB ERD

이 문서는 MVP 통합 기획 문서와 Lazyweb 기반 화면 디자인 제안 보고서를 토대로, 홈/행사 목록/행사 상세/내 기록장/관리자 초안 검수 화면을 지원하기 위한 데이터 모델 관계를 정리한 설계 문서입니다.

설계 범위

현재 구현 계획의 첫 MVP는 Event와 EventDraft 중심입니다. 화면 디자인 보고서에서는 상태 저장, 내 기록장, 사용자 사진까지 필요하므로 ERD에는 확장 모델도 함께 표시합니다. 단, 확장 모델은 즉시 구현 범위가 아니라 화면 설계와 이후 백엔드 계획을 연결하기 위한 데이터 설계 후보입니다.

엔티티 정의

엔티티 목적 주요 화면 구현 단계
Event 관리자 검수를 통과해 공개 목록과 상세에 노출되는 행사 데이터 홈, 행사 목록, 행사 상세 MVP Core
EventDraft 공식 URL에서 추출한 미검수 후보 데이터와 승인/반려 상태 관리자 초안 생성, 관리자 초안 검수 MVP Core
UserEventStatus 사용자가 행사에 대해 가진 관심 있음, 방문 예정, 다녀옴, 놓침 상태 행사 카드, 행사 상세, 내 저장 목록 Screen-driven Extension
VisitRecord 다녀온 행사에 대한 날짜, 한줄 후기, 만족도, 대기 시간, 메모 방문 기록 작성, 내 기록장, 월별 타임라인 Screen-driven Extension
VisitRecordPhoto 사용자가 직접 업로드한 방문 기록 사진 기록 카드, 기록 상세 Screen-driven Extension
EventSubmission 사용자 제보 URL을 받아 검수 흐름으로 넘기기 위한 후순위 모델 사용자 제보 화면, 관리자 제보 검토 Deferred/Future

관계와 제약

관계 카디널리티 설계 이유 주요 제약
EventDraft -> Event 0..1 draft creates 0..1 event 초안은 반려될 수 있고, 승인된 초안만 게시 Event가 됩니다. 자동 게시 금지, 승인 시에만 Event 생성
User + Event -> UserEventStatus 1 user/event pair has 0..1 status 목록과 상세에서 상태 버튼을 직접 노출하기 위해 사용자별 상태를 분리합니다. UNIQUE(user_id, event_id)
User + Event -> VisitRecord 1 user/event pair can have many records 재방문이나 같은 작품 행사 반복 방문 가능성을 막지 않습니다. 방문 기록은 소유 사용자만 수정/삭제
VisitRecord -> VisitRecordPhoto 1 record has 0..N photos 사진은 직접 업로드한 방문 기록에만 저장한다는 이미지 정책을 반영합니다. 공식 이미지, SNS 이미지, 포스터 이미지는 저장하지 않음
EventSubmission -> EventDraft 0..1 submission converts to 0..1 draft 사용자 제보는 후순위지만 URL 기반 검수 흐름으로 연결할 수 있어야 합니다. 공식 URL 검증 후 변환

화면별 데이터 요구사항

홈 / 행사 목록

  • Event.publish_status = published만 조회
  • 지역, 기간, 카테고리, 키워드 필터
  • D-Day와 진행 상태는 저장하지 않고 날짜로 계산
  • 로그인 사용자는 UserEventStatus를 함께 조회

행사 상세

  • Event의 공식 URL, 장소, 기간, 요약 표시
  • 상태 변경 버튼은 UserEventStatus upsert
  • "다녀옴" 전환 후 VisitRecord 작성으로 연결

내 기록장

  • VisitRecord.visited_on 기준 월별 그룹
  • 사진 수는 VisitRecordPhoto 집계
  • 작품/지역 필터는 연결된 Event 필드 사용

관리자 초안 검수

  • EventDraft.status 기준 pending/approved/rejected 목록
  • 원문 근거는 raw_title, raw_text에 제한 저장
  • 승인 시 Event.official_url 중복 검사

권장 필드 초안

MVP Core

모델 필드

모델 필드

구현 순서 제안

  1. Event: 공개 목록/상세와 필터를 먼저 지원합니다.
  2. EventDraft: URL 기반 초안 생성, 관리자 검수, 승인 게시 흐름을 붙입니다.
  3. UserEventStatus: 화면 카드와 상세의 상태 버튼을 지원합니다.
  4. VisitRecord: "다녀옴" 이후 기록 작성과 내 기록장을 지원합니다.
  5. VisitRecordPhoto: 사용자 직접 업로드 사진만 저장합니다.
  6. EventSubmission: 사용자 제보가 필요해질 때 후순위로 추가합니다.
Deferred Refactoring Note

작품, 캐릭터, 장소, 출처를 별도 정규화 테이블로 분리하는 작업은 현재 화면 요구사항에는 과합니다. 검색 품질, 중복 장소 정리, 작품별 통계가 실제 요구될 때 Work, Venue, Source 모델 분리를 검토합니다.
