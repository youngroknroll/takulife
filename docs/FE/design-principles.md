## ① 브랜드 성격

성격 단어 4개: 단정하다 · 밀도 있다 · 정렬되어 있다 · 조용하다 `[문서 작성자 제안 2026-11-03, 사용자 확인 대기 — ⑬-14]`.

방향 한 줄: **밝은 회색 화면 위에 이중선 창을 놓고, 선택은 반전 막대로 알린다. 색은 선택(반전)·링크·오류·점에만 쓰고, 괘선과 숫자 정렬로 한 화면에 기록을 많이 보인다.**

- "dos 시절의 레이아웃, 폰트는 현재 그대로, 하지만 too mouch bold는 금지."가 DOS 방향의 원문이다 `[문서 사용자 결정 2026-11-15]`. 서체는 Pretendard 그대로이고 모노스페이스를 쓰지 않는다. "레트로이되 화려하지 않게" `[문서 사용자 결정 2026-11-02]`는 유지된다.
- "블랙앤그레이 형태… 강조되어야 하는 곳들에만 색… 카테고리도 작은 동그라미 아이콘에만"은 2026-11-03 A4 확정 때의 원문이다 `[문서 사용자 결정 2026-11-03]`. 색을 역할에만 쓰는 제한은 DOS에서도 유지되고, 색의 값과 창·반전 형태는 DOS가 대체한다(⑫).
- 이 사이트는 구매·결제 서비스가 아니라 기록하는 도구다. 장식으로 시선을 끌지 않고, 기록이 한 화면에 많이 보이는 쪽을 택한다.

## ② 디자인 원칙

### 원칙 1. 색은 역할이다

무채색(바탕·표면·글자·보조 글자·단선·비활성) 위에 색은 4개 역할에만 쓴다: 선택(진한 파랑 반전), 링크(틸), 점(카테고리 7색·시리즈 12색), 오류(빨강). 색 값은 ⑤·⑩에 있다 `[문서 사용자 결정 2026-11-15·2026-11-17]`.

- 그래서 하지 않는 것: 장식·분위기·"브랜드 느낌"을 위해 색을 칠하지 않는다. 역할이 없는 색은 무채로 돌린다. 점 외의 종류·상태 구분은 색이 아니라 형태(기호, 테두리 모양)와 글자로 한다 `[문서 사용자 결정 2026-11-17: "시리즈 색 점은 유지"]`.

### 원칙 2. 면이 아니라 창·단선·반전으로 위계를 만든다

위계는 창(`3px double` 이중선), 단선(1px), 굵은 선(2px), 반전 막대, 글자 크기로 만들고, 카드·그림자·색 면으로 만들지 않는다. 선 굵기 값은 ⑦·⑩(a)의 `--bw-1`·`--bw-2`·`--bw-3`이다.

- 목록 행은 한 줄 행 구조를 유지하되 카테고리·지역을 제목 아래 줄로 둔다 `[문서 사용자 결정 2026-11-17: "카테고리·지역을 제목 아래로"]`. DOS 시안의 1440×800 첫 화면에는 행 12개가 온전히 보이고 행 높이는 46.5px(2줄 제목 행 66.5px)이다 `[실측 Chrome DevTools 2026-11-17, 문서 시안 설계안 "목록 메타 위치 변경"]`. (A4 시안의 20행·32px은 이력이다 `[실측 2026-11-03 Chrome 156]`.)
- 그래서 하지 않는 것: 카드 안에 카드를 넣지 않고, 창 안에 창을 중첩하지 않으며, 구획을 그림자·반투명·색 면으로 나누지 않는다. 창은 쪽의 주 구획이고, 부 구획은 창 안 단선 + 소제목으로 나눈다 `[문서 WED 사전 검토 2026-11-17]`.

### 원칙 3. 상태는 형태로도 말한다

색을 못 보는 상태에서도 의미가 전달돼야 한다. 선택·눌림·현재는 반전(배경과 글자색을 함께 바꿈), 링크는 항상 밑줄이다. 상태는 테두리 모양으로 나눈다:

| 대상 | 형태 |
|---|---|
| 방문 예정 / 완료 / 놓침 | 1px `--select` 테두리 / `--select` 채움 + 흰 글자 / 1px dashed `--rule` 테두리 `[코드 dos.css:603-617]` |
| 컬렉션 보유 / 구함 / 교환 / 미보유 | `--select` 채움 / 1px `--ink` 테두리 / 3px double `--ink` 테두리 / 1px dashed `--rule` 테두리 `[문서 WED 사전 검토 2026-11-17]` |
| 찜 | 1px `--ink` 테두리 + ♥ 글리프(비찜 ♡) |
| 활동 달력 종류(일정·찜·방문·굿즈) | 일정 ○ · 찜 ♥ · 방문 ■ · 굿즈 ● (칸 안·범례 모두). 찜은 다른 화면의 찜 표시(♥)와 같은 기호를 쓴다 `[문서 사용자 결정 2026-11-17, WED U12]` `[문서 오케스트레이터 결정 2026-11-17 — 사용자의 명시 답은 없고, 이 대응인 채로 PR #420이 머지 승인됐다]` |

모든 상태 칩에는 글자 라벨이 있다. 기호는 라벨을 대체하지 않는다.

- 근거: 링크 색과 본문 글자의 대비가 2.85:1로 3:1 하한 아래이고(⑤ 대비비 표 "링크/본문 글자"), 색만으로 링크를 구분할 수 없다. 그래서 밑줄은 어디서나 항상 켠다.
- 그래서 하지 않는 것: 색 하나로만 상태를 구분하지 않는다.

1. 색 리터럴은 토큰 블록에만 둔다. 컴포넌트·페이지 CSS에서 `#hex`·`rgb()`를 쓰지 않는다. 지금 `tokens.css` 밖의 색 리터럴은 0줄이다 `[실측 ac1_count 2026-11-17, 스태프·dist 제외]`. forced-colors 블록의 시스템 색 키워드(`ButtonText` 등)는 토큰 대상이 아니다. 재현: `rg -n '#[0-9a-fA-F]{3,6}\b|rgba?\(' static/css | rg -v 'tokens.css|/staff/|/dist/'`. 트랙 58 착수 전의 우회 사례(`button.css:29`의 `#fff`, `cards.css:98`의 `#46617f`, `archive_collection.css`의 `#fff` 5곳 등 `[실측 rg 2026-11-03]`)는 삭제됨(트랙 58)이다.
2. 대비 하한: 글자 AA 4.5:1, 비텍스트(단선·점·포커스 링) 3:1 `[문서 WCAG 2.2 AA SC 1.4.3·1.4.11]`. 터치 타깃은 터치 조건(≤44.99rem 또는 `pointer: coarse`)에서 44px `[문서 AGENTS.md "Frontend Work Policy"(폐지된 규칙이라 정보 항목); 코드 tokens.css:128-134, dos.css:50-55]`, WCAG 2.2 AA(SC 2.5.8) 하한은 24px이고 데스크톱 행 안 찜 24px·컨트롤 32px는 이 하한 이상이다.
3. 예외: 비활성 컨트롤은 WCAG 대비 예외다. 그래서 비활성 색은 정보 글자에 쓰지 않는다.

- 서체: Pretendard 단일 `[문서 사용자 결정 2026-11-02·2026-11-15: "폰트는 현재 그대로"]`. 폰트 패밀리 이름은 `'Pretendard'`이고 `Pretendard Variable`이 아니다 `[코드 static/fonts/pretendard/pretendardvariable-dynamic-subset.css:14]`.
- 크기 5단계(0.75 / 0.875 / 1 / 1.25 / 1.75 rem), 굵기 2단계(400·700), 행간 2단계(1.25 / 1.5)다 `[코드 dos.css:31-39, 로컬 시안]`. 값은 ⑩(a)에 있다.
- **굵기 700은 쪽 h1과 로고뿐이다.** 그 밖은 전부 400이다: h2~h4, 창 제목, 버튼 글자, `b`·`strong`·`th`(UA 기본 굵기를 400으로 되돌린다), 통계 숫자, 제목 링크. 강조는 굵기가 아니라 반전·테두리·크기로 한다 `[문서 사용자 결정 2026-11-15: "too mouch bold는 금지"]`. 오늘·선택 날짜 숫자도 굵게 하지 않는다.
- 자간: 기본값만 쓴다. 자간 토큰과 `text-transform`은 없다 `[코드 dos*.css: letter-spacing·text-transform 0건, 실측 grep -c 2026-11-17]`. 운영 공개 CSS도 두 선언이 0줄이다 `[실측 python 2026-11-17, 스태프·dist 제외]`.
- 제목 링크는 굵기 400이다 `[문서 사용자 결정 2026-11-03: "제목 굵기 400으로"]`. 링크는 색과 밑줄로 구분하고 굵기로 구분하지 않는다.
- 숫자는 `tabular-nums`를 body에서 전역으로 켠다 `[코드 dos.css:85]`. Pretendard 서브셋의 `tnum` 제공 여부는 A4 시안에서 폭 동일(`'1111/11/11'`과 `'0000/00/00'`이 78.15px)로 확인했다 `[실측 2026-11-03 Chrome 156 측정 M16, 이력]`.

- 쓰지 않는 것: 글자 크기를 위계 표현 외의 이유(장식)로 키우는 것, 넓은 자간 라벨(③ eyebrow는 글자를 유지하되 자간 없음), 굵기 300, 굵기 700의 확대.

- **행 전체가 눌리는 행과 균등 격자(홈 스냅샷 두 곳)**: ① 행 전체가 눌리는 행은 제목 링크의 `::after`(`position: absolute; inset: 0 0 calc(-1 * var(--bw-1)) 0`, `static/css/pages/home.css:464`의 `.snapshot-record-title a::after`)를 `position: relative`인 행으로 늘려 만들고 행 아래 1px 선까지 덮는다. 말줄임 상자(`p`)에 `overflow: hidden`이 있으면 링크의 포커스 링(2px + offset 2px = 4px `[계산]`)이 잘린다. 그래서 `p`에 4px 안쪽 여백과 같은 크기의 음수 바깥 여백을 주고, 말줄임은 링크(`display: block`)가 맡는다 `[실측 2026-11-18 Playwright 3개 브라우저, 잘림 0px]`. 같은 행의 보조 링크는 같은 행의 보조 링크('기록')는 `position: relative`로 그 위에 둔다. z-index는 쓰지 않고, 제목 링크와 행 사이 조상(본문·`p`)에는 `position`·`transform`·`contain`을 주지 않는다(주면 늘어난 영역이 그 조상에 갇힌다). ② 그런 행은 `row-invert`를 쓴다. 보조 링크의 글자색은 반전 상태에서 상속으로 되돌려야 하는데, 페이지 CSS가 공용 규칙(`cards.css`) 뒤에 로드돼 같은 명시도면 페이지 규칙이 이기므로 `.snapshot-record-row.row-invert …`처럼 명시도를 높인 규칙이 필요하다. 보조 링크 자신에 hover·`:focus-visible`이 오면 반전 행 안에서 한 번 더 뒤집어(`--on-select` 바탕, `--select` 글자) 행 상세 링크와 구분한다. ③ 눌리지 않는 행(링크 없는 비공개 행사)에는 `row-invert`를 붙이지 않는다. ④ 균등 격자의 선은 border로만 긋는다: 위·왼쪽은 격자가, 오른쪽·아래는 칸이 긋는다. 빈 칸도 같은 선을 가진 `aria-hidden` 칸으로 채운다(`gap`+배경색 방식 금지). 5칸 격자의 칸 폭은 203.4px(뷰포트 1280px), 3칸 격자는 111.7px(뷰포트 390px)이고 칸 안쪽 여백은 8px이다 `[실측 2026-11-18 Playwright chromium]`. ⑤ 이 패턴은 홈 스냅샷 두 곳에만 쓴다. 행사 목록 행 3종(`.event-compact-row`·`.event-index-row`·`.agenda-row`)은 제목만 눌리는 지금 동작을 유지한다 `[문서 사용자 결정 2026-11-18: "'기록 대기' 행만"]`.
- **내비 크기·선**: 주 내비 글자는 `--fs-2`, 헤더 아래 선 2px, 하단 기능 막대 위 경계 2px이다 `[코드 site-chrome.css]`.

### (d) 시안으로는 결정되지 않아 구현이 채울 범주

1. **구 토큰 → 신 토큰 대응표 완성**: (b)는 역할 단위다. 상태·액센트 soft/ink 참조(수치는 (e) 첫 행)의 이동처를 줄 단위로 정한다.
2. **컴포넌트 규칙**: (f)에 정리했다.
3. **시안이 CSS에 직접 쓴 값(컴포넌트 상수)**: 그리드 열 폭, aside 폭, 헤더 `min-height` 3rem, 행 `min-height` 2rem, `z-index` 50·40·100, 밑줄 오프셋 0.2em, 점 0.5rem·50%, `scroll-padding-top` 3.5rem, `outline-offset` 2px(안쪽 -2px), 스킵 링크 `top -4rem`, 읽기 전용 칩 `min-height 1.5rem`(`--hit-sm`과 같은 값이라 치환 가능), 체크박스 1rem `[코드 dos.css:73,128-129,159,193,576-577]`. A4 시안에서 정리한 열 폭 목록(3.5·7·10·6.5·5.5·6·3 rem)은 이력이고 DOS 시안은 열 폭이 다르다(목록 행은 작품 6rem + 제목 2열 grid `[문서 시안 설계안 "목록 메타 위치 변경"]`). 이 값들은 기본적으로 컴포넌트 상수다 `[문서 docs/plan-archive/track-57.md D3]`. 다른 값과 함께 움직여야 하는 것(헤더 높이와 `scroll-padding-top`·스킵 링크 오프셋 — 헤더 높이는 운영에 이미 역할 토큰 `--site-header-h`가 있다 `[코드 static/css/components/site-chrome.css:29]`, 읽기 전용 칩 `min-height 1.5rem`과 `--hit-sm`)은 역할 토큰 후보라 구현이 운영 값을 재서 정한다.
4. **브레이크포인트 상수**: 경계 2개 — 45rem(시안은 터치 44px·내비 접힘이 `max-width: 44.99rem`, 좌우 패딩 확대가 `min-width: 45rem`인 같은 경계의 보수 쌍. 운영은 위 (c) 표대로 `max-width: 45rem`이 주이고 `44.99rem`은 터치 44px 토큰 하나뿐이다)과 56.25rem(필터·결과 2열). 70rem은 한 줄 행의 A4 경계였고 DOS 시안은 56.25rem을 쓴다 `[코드 dos.css:179,756; 문서 시안 설계안 "목록 메타 위치 변경": ≥56.25rem]`.
5. **스태프 생성 카테고리 슬롯 7~11 점 색**: 시안은 고정 슬러그 7개만 다룬다. 슬롯은 5개다 `[계산 슬롯 7~11]` `[코드 tokens.css:75-84]`. 스태프가 만든 카테고리의 점은 배정 슬롯의 잉크 색이고, 슬롯이 없으면 `--ink-2`다 [문서 사용자 결정 2026-11-17 "새 카테고리에도 색 점"]. ⑬ 참조.
6. **시안에 없는 컴포넌트**: 행사 상세·컬렉션·폼·모달·토스트·사진 올리기·계정 쪽. 공통 어휘(⑩(f))를 적용하고 어긋나는 구조는 보고한다.
7. **반경 토큰 없음**: 규칙으로 대체했다(⑦). 가드는 정리 단계에서 `border-radius` 리터럴(점 외)을 막는 검사로 만든다.
