# 행사 타이포그래피 에디토리얼

## Current fact

공개 행사 경험은 포스터를 전제로 구성돼 있다. `Event.poster_image`가 공개 목록,
홈, 행사 상세, 스태프 품질 경고와 업로드 API에 연결돼 있으며, 이미지가 없을
때는 이니셜 타일·그라디언트·워터마크로 빈자리를 채운다.

행사 발견은 takulife의 최종 목적지가 아니라 방문 기록과 컬렉션 기여로 이어지는
진입점이다. 따라서 포스터의 시각적 풍부함보다 공식 정보의 신뢰도와 제목·날짜를
빠르게 비교하는 능력이 우선한다.

## Decision

2026-08-14 사용자 승인으로 서비스 전체의 공식 포스터 운영을 끝낸다.

- 공개 목록, 달력, 홈, 행사 상세, 활동 화면과 스태프 화면에서 포스터 및
  포스터 대체 장식을 사용하지 않는다.
- `Event.poster_image`, 포스터 업로드·교체·삭제 API와 관련 운영 지표를 제거한다.
- 저장된 포스터는 목데이터이므로 백업하지 않고 영구 삭제한다.
- 행사 정보의 시각적 중심은 작품명·행사명이고 날짜를 같은 시선 흐름에서 두 번째
  축으로 강조한다.
- Eventernote의 정보 중심 접근을 참고하되 화면을 복제하지 않는다. takulife는
  여백, 제목 위계, 날짜 열과 얇은 규칙선을 사용하는 에디토리얼 인덱스를 쓴다.

## Experience specification

### 행사 목록

기본 행은 왼쪽 날짜 열과 오른쪽 정보 열로 구성한다. 작품명은 짧은 표제,
행사명은 가장 큰 제목, 장소·전체 기간·카테고리·상태는 보조 정보로 둔다.
카드 테두리와 그림자 대신 여백과 규칙선으로 행을 구분한다. 카테고리 색은 작은
표식이나 짧은 선에만 쓰고 넓은 색면과 그라디언트는 쓰지 않는다.

모바일에서는 날짜를 제목 위 한 줄로 옮기고 세로 목록을 유지한다. 긴 한글·일본어·
영문 제목은 말줄임표 없이 줄바꿈한다. 날짜나 장소가 없으면 각각 `일정 미정`,
`장소 미정`을 표시해 누락을 장식으로 숨기지 않는다.

### 서비스 전체

- 홈의 포스터 덱과 행사 포스터 레일을 큰 제목·날짜 표제와 세로 텍스트 목록으로
  교체한다.
- 달력 칸에는 짧은 행사명과 상태 표식만 두고, 선택 결과는 같은 에디토리얼 행
  체계로 연결한다.
- 행사 상세는 포스터 열을 없앤 단일 콘텐츠 칼럼으로 구성한다. 작품명, 행사명,
  날짜, 장소, 운영 시간, 공식 출처, 상태와 사용자 행동을 문서 표제처럼 배치한다.
- 관련 행사와 활동 화면의 예정 행사는 날짜·제목·장소를 갖춘 축약형 텍스트 행을
  사용한다.
- 스태프 검수는 공식 URL, 출처명, 기간, 장소, 작품명과 재검증 상태에 집중한다.
- 행사별 공유 이미지를 만들지 않고 서비스 공통 브랜드 이미지만 사용한다.

### Interaction and accessibility criteria

- 날짜는 의미 있는 `time` 요소로, 작품명과 행사명은 올바른 제목 계층으로
  구성한다.
- 상태는 색뿐 아니라 `진행 중`, `오픈 예정`, `종료 임박`, `종료` 텍스트로
  전달한다.
- 행의 탐색 링크와 찜 버튼의 클릭·포커스 영역은 겹치지 않는다.
- 필터, 정렬, 목록·달력 전환, 찜의 키보드 조작과 기존 실패 복구를 유지한다.
- 찜 요청 중 중복 입력을 막고 실패 메시지를 해당 행사 행 안에서 알린다.
- 모바일에 행사 가로 스크롤 목록을 새로 만들지 않는다.
- 라이트·다크 테마에서 긴 제목, 누락 정보, 빈 결과와 상태색을 확인한다.

## Guardrail

- 행사 수집·게시 경로는 이미지 URL이나 이미지 파일을 받거나 외부에서 가져오지
  않는다.
- 포스터가 없음을 표현하는 이니셜 타일, 그라디언트, 워터마크도 만들지 않는다.
- 이미지 제거를 이유로 날짜·장소·공식 출처의 정보 품질 기준을 낮추지 않는다.
- 이미지 파일 영구 삭제는 승인된 목데이터에만 적용한다. 이후 컬렉션·방문 기록의
  사용자 사진 보존 정책으로 일반화하지 않는다.
- 동적 공유 이미지 생성, 새 폰트 의존성, 행사 추천 로직 변경과 정보 모델 확장은
  이번 범위 밖이다.
- 삭제된 목이미지 2,869개(14M) `[실측 2026-08-15]`는 백업이 없어 복구할 수 없다.
  포스터 없음을 메우려는 어떤 대체 장식(이니셜 타일·그라디언트·워터마크 등)도
  재도입하지 않는다.
- `Event.poster_image`를 되살리는 결정은 이 문서가 아니라 새 제품·저작권·운영
  승인과 별도 마이그레이션을 요구한다. 이번 삭제를 근거로 조용히 되돌리지 않는다.

## Domain boundary and dependency direction

`events`는 공개 행사 데이터와 포스터 필드·API 제거를 소유한다. `web`은 그
데이터를 포스터 없이 표현하고, `archive`는 기존 사용자 찜·방문·컬렉션 상태를
계속 소유한다. 승인된 `archive -> events` 의존 방향은 바뀌지 않는다.

포스터 제거는 새 교차 도메인 서비스나 저장소 추상화를 만들지 않는다. 기존
이미지 저장 기반은 컬렉션과 방문 사진 때문에 유지하며, 행사 전용 참조만 없앤다.

## 홈 히어로 로테이터 (2026-08-16 확장, 같은 날 티켓 스텁으로 개편)

홈 히어로 대표 행사가 단건 정적 표제에서 최대 5건 타이포 자동 슬라이드로
확장됐다. 컨텍스트 계약은 `featured_event_rows`(리스트, 최대 5건, 진행중→예정
우선순위)이고 단수 키 `featured_event_row`는 더 이상 존재하지 않는다.

### 티켓 스텁 개편 (2026-08-16, claude.ai/design 보드 2c 채택안)

히어로가 `.hero-ticket` 카드(surface + 테두리 + 그림자, `minmax(0,1fr) 340px`
그리드)로 바뀌었다. 좌측 `.hero-ticket-main`은 eyebrow·h1·검색·칩, 우측
`.hero-ticket-stub`은 brand-soft 배경의 티켓 반쪽 — 점선 절취선(2px dashed)과
`--bg` 색 notch 2개(펀치홀 흉내, aria-hidden)로 분리된다. 슬라이드 내용은
admit(`<span lang="en">ADMIT ONE</span> · 상태라벨`) → 작품 → 제목(h2) →
날짜/장소(`<br>` 두 줄) → 대형 D-day → 바코드(장식) → 자세히 보기.

- 로테이터 계약은 그대로다: 다건 분기에서만 `.hero-ticket-stub`에
  `hero-rotator-wrap`을 **이중 클래스**로 얹는다(JS는
  `closest(".hero-rotator-wrap")`만 본다). JS 파일은 무변경.
- 대형 D-day 분기: ended=「종료」 / closing_soon·ongoing=D-n·오늘 종료 /
  upcoming=오픈 D-n·오늘 오픈 / dday None(날짜 미정)=요소 생략. `{% if
  row.dday is not None %}` 가드를 쓴다(Django if는 `is not`·None 리터럴 지원).
- **함정: 공유 cards.css의 `.hero p`(특이도 0,1,1)가 단일 클래스 p 규칙
  (0,1,0)의 color·margin을 이긴다.** 그래서 eyebrow·admit·work·meta·dday
  규칙은 `.hero-ticket` 하위로 스코프해 (0,2,0)으로 올렸다. 45rem의 dday
  재선언도 같은 특이도로 맞춰야 모바일 축소가 캐스케이드에서 안 죽는다.
  이 스코프를 "불필요한 중첩"으로 풀면 색·여백이 조용히 무너진다(실측으로
  확인된 결함이었다). 옛 마스트헤드는 span·flex-gap 구조라 이 함정을 우연히
  피해갔고 상태 문구 색만 조용히 눌려 있었다.
- 슬라이드별 바코드 중복은 승인된 구조다(장식 aria-hidden, inert가 비활성
  슬라이드를 통째로 배제) — 중복 정리 리팩터 금지.

- 0건은 기존 빈 상태, 1건은 컨트롤 없는 정적 표제, 2건 이상만 로테이터가 된다.
  도트·정지 버튼은 `static/js/pages/home_hero_rotator.js`가 주입한다 — no-JS에서
  죽은 컨트롤이 남지 않게 하기 위한 구조라 서버 렌더로 되돌리면 안 된다.
- 슬라이드 은닉은 `hidden`이 아니라 grid 겹침 스택 + `visibility:hidden`이다.
  컨테이너 높이가 가장 긴 슬라이드에 고정되는 것이 이 선택의 절반의 이유이고
  (전환 중 CTA 좌표 고정 = 오클릭 방지), no-JS 안전이 나머지 절반이다.
- **전환 시 `inert`를 is-active 전환과 같은 틱에 걸어야 한다.** CSS의 visibility
  지연(350ms) 동안 나가는 슬라이드가 tabbable로 남는 이중 창이 실측으로 확정된
  결함이었고 JS `inert`가 그 창을 닫는다. CSS만 보고 inert를 "불필요한 중복"으로
  지우면 결함이 재발한다.
- 도트 클릭은 자동 회전 영구 정지다(토글로만 재개). 저장소 hscroll 관례(리셋 후
  재개)와 다른데, WCAG 2.2.2의 "사용자 정지 상태 유지"를 위해 의도한 이탈이다.
- reduced-motion에서는 자동 회전과 정지/재생 토글 자체가 없다(도트 수동만).
  게이트 산출물·오케스트레이터 확정 결정·실측 증거 전문은
  `.docs/FE/hero-rotator-gate-preimpl.md`(gitignore, 작업 기록)에 있다.

## Known gap

스크린리더 실재생(VoiceOver/NVDA) 검증은 이번에도 실시하지 않았다. 이 트랙이
만든 회귀가 아니라 저장소 전체가 아직 갖지 못한 검증 범위다.

로테이터의 bfcache `pageshow persisted` 분기는 DevTools 부착 자동화에서 bfcache가
체결되지 않아 코드 검토로만 확인됐다(theme.js 관례와 동일 패턴). 실제 뒤로가기
제스처로 재확인할 수 있게 되면 그 항목만 실측을 보완하라.
