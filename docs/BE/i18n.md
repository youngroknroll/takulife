# UI 다국어(ko/en/ja/zh-hans) — 기술 기록(트랙 43-1)

상태: **43-1 구현됨(2026-10-21, 미머지)** — 공개 셸·홈·계정(allauth)·공용 JS의 UI 문구를
Django gettext로 옮겼다. 이벤트 상세·컬렉션·활동·마이페이지는 43-2·43-3이다.
이 문서는 **가드레일만** 담는다. 계획·결정 이력은 `prompt_plan.md` 트랙 43 절이 정본이다.

## Current fact

- 언어 결정은 **쿠키 → `Accept-Language` → `ko`** 순서이고 URL 접두사는 없다.
  `LocaleMiddleware`는 `SessionMiddleware`와 `CommonMiddleware` 사이에 있다
  (`config/settings.py:334`). `LANGUAGE_CODE="ko"`(403), `LANGUAGES`는 ko·en·ja·zh-hans
  4개(405), `LOCALE_PATHS=[BASE_DIR/"locale"]`(411), `i18n` 컨텍스트 프로세서(368).
- 언어 쿠키는 `Secure`(기존 `SECURE_COOKIES` 스위치)·`SameSite=Lax`·`HttpOnly`다
  (`config/settings.py:557-559`). 전환은 푸터 폼이 `/i18n/setlang/`에 POST한다
  (`config/urls.py:27`, Django 표준 뷰). JS 번역 사전은 `/jsi18n/`
  (`config/urls.py:26`)이 내려준다.
- 원문(msgid)은 **한국어**다. `ko`는 카탈로그가 없고 msgid가 그대로 나온다.
  카탈로그는 `locale/{en,ja,zh_Hans}/LC_MESSAGES/{django,djangojs}.po` 6개이며
  `.mo`는 커밋하지 않는다(`.gitignore`). 언어당 메시지는 django 308건 + djangojs
  27건이다 `[실측 msgfmt --statistics 2026-10-21]`.
- 스태프 화면은 쿠키 언어와 무관하게 항상 한국어다. Django 뷰는
  `staff_console_required`(`staff/permissions.py:25`), DRF 뷰는 `staff_api_korean`
  (`staff/permissions.py:31-46`, `staff/urls.py`·`staff/api_urls.py`의 DRF 라우트 12개
  전부)가 `translation.override("ko")`로 감싼다. 스태프 셸은 카탈로그 없이
  `i18n_fallback.js`만 로드한다(`templates/staff/base_staff.html:81`).
- 인증이 필요한 API의 403 본문에는 언어 무관 `code: "not_authenticated"`가 실린다
  (`core/api_exceptions.py`, `config/settings.py:618`). 프론트는 `detail` 문구를 비교하지
  않고 이 `code`로 로그인 안내를 띄운다(`static/js/shared/api.js`).

## Decision

- **쿠키 방식, URL 접두사 없음**: `i18n_patterns`를 접두사 없는 기본 언어로 쓰면
  접두사 없는 `/api/` 요청이 `LANGUAGE_CODE`로 강제되고(`django/middleware/locale.py`),
  접두사를 붙이면 한국어 URL 전체와 테스트 리터럴 URL이 바뀐다. 외국어 SEO·hreflang은
  이연이다.
- **번역 호출은 문구가 적힌 자리에서 감싼다**: 모듈·클래스 수준(폼 라벨, `core/vocab.py`
  라벨)은 `gettext_lazy`, 요청 처리 함수 안은 `gettext`. 문구를 한 층으로 끌어모으지 않는다.
- **DB 카테고리 라벨·행사 콘텐츠·사용자 입력은 번역하지 않는다.** 화면에서는
  `lang="ko"`로 표시한다. 지역 라벨 `REGION`은 필터 어휘라 번역한다.
- 일본어·중국어는 사용자의 검수 시트 확인 전에는 production에 내보내지 않는다
  (`docs/deploy-runbook.md` §3-18).

## Guardrail

1. **`compilemessages`는 반드시 `--ignore .venv`.** 이 명령은 `./locale`만 보지 않고
   현재 디렉터리 전체를 순회해 이름이 `locale`인 폴더를 전부 수집한다
   (`django/core/management/commands/compilemessages.py:85-100`). 설정 모듈을 줘도
   순회는 일어난다. 빼면 `.venv` 서드파티 `.po` 1280개를 다시 컴파일한다
   `[실측 로그 1282줄]`.
2. **`msgfmt --check-format`은 `javascript-format` 불일치를 잡지 못한다**(종료 코드 0,
   python-format만 종료 코드 1) `[실측 msgfmt 프로브]`. 그래서 번역문의 자리표시자·
   HTML 태그를 원문과 비교하는 테스트가 유일한 안전망이다
   (`tests/core/test_i18n_catalog_completeness.py`).
3. **번역문의 HTML 태그는 속성까지 글자 그대로 원문과 같아야 한다.** `blocktranslate`
   본문과 `mark_safe`(`accounts/forms.py` 약관 동의 라벨)는 msgstr을 HTML로 그대로 렌더한다.
   번역가가 `onmouseover` 같은 속성을 넣으면 XSS가 된다. 태그 **이름**만 비교하던 가드는
   속성 주입을 통과시켰다 `[실측 뮤테이션]`.
4. **지연 번역 객체는 `str`이 아니다.** `json.dumps`는 못 직렬화한다 — 지역 라벨이
   JSON-LD payload에 들어가는 간접 경로에서 터졌다(`web/views/events.py:540`,
   `DjangoJSONEncoder`로 해결). `str` 전용 API(`", ".join`, `json.dumps`, 정규식)에 라벨을
   넘기기 전에 소비처를 `rg`로 추적한다.
5. **언어에 따라 달라지는 문구를 서버 응답의 문자열로 비교하지 않는다.** DRF·Django 내장
   문구는 `LocaleMiddleware`가 켜지는 순간 활성 언어로 번역된다. 판별은 언어 무관 `code`로.
6. **서식 문자열에 한국어를 박지 않는다.** `date:"n월 j일"`은 외국어 화면에 한국어를 섞는다.
   `DATE_FORMAT`·`MONTH_DAY_FORMAT`과 월 이름 `F`를 쓴다(한국어 출력은 글자 단위로 같다).
   `tests/core/test_ui_korean_literal_guard.py`가 템플릿·JS의 번역 태그/`gettext` 밖 한국어를
   막는다. **이 가드는 승인 범위 파일 목록을 직접 가지고 있다 — 43-2·43-3에서 범위를 넓힐 때
   목록과 기대 개수를 함께 갱신한다.**
7. **500 페이지는 컨텍스트 프로세서 없이 렌더된다.** `<html lang>`은 변수가 아니라
   `{% get_current_language %}` 태그로 얻고(`templates/base.html:1`), 404·429·500 템플릿에는
   변수 보간 `blocktranslate`를 쓰지 않는다. 전환기는 `{% if request %}` 안에서만 렌더한다.
8. **언어 전환기의 언어명은 자기 표기다.** `{% get_available_languages %}`는 이름에 `gettext`를
   적용해 한국어 화면에서 English가 "영어"로 나온다. `get_language_info_list`의
   `name_local`을 쓴다(`templates/core/partials/_site_footer.html:60`).
9. **스태프 DRF 라우트를 추가하면 `staff_api_korean`으로 감싼다.**
   `tests/staff/test_staff_api_language.py`의 전수 가드가 12개를 센다 — 라우트가 늘면 숫자와
   함께 갱신한다. DRF 응답 렌더는 뷰 반환 뒤로 미뤄지므로 데코레이터가 같은 구간에서 렌더까지
   끝낸다.
10. **`set_language`는 허용 목록이 아니라 로케일 파일 존재로 쿠키를 정한다**
    (`django/views/i18n.py:60-62`). Django에 번역이 있는 미지원 언어(fr)도 쿠키는 설정되지만
    읽을 때 `LANGUAGES`에 없어 무시된다. 허용 목록은 `LANGUAGES` 하나다.
11. 번역 문자열을 DB·로그·분석 이벤트·세션에 저장하지 않는다(요청자 언어가 저장 데이터에
    섞인다). 로거 메시지에 `gettext`를 쓰지 않는다(`tests/core/test_error_logging_policy.py`).
12. e2e 브라우저가 영어 `Accept-Language`를 보내면 화면이 영어가 되어 한국어 선택자가
    깨진다. 이 환경의 Playwright Chromium은 헤더를 보내지 않아 ko로 렌더된다
    `[실측 2026-10-21, tests/e2e 10 passed]`. 환경이 바뀌면 컨텍스트 `locale`을 고정한다.

## Known gap

- 43-2(이벤트)·43-3(컬렉션·활동·마이페이지)과 아카이브 날짜 서식(`n월`)은 아직 한국어다.
- 파이썬 한국어 문자열 리터럴이 gettext 밖에 남았는지 찾는 가드는 없다(AST로 "감쌌는가"를
  판별하기 어렵다). 템플릿·JS만 가드한다.
- 카탈로그 로드 실패 경로(`/jsi18n/` 실패 시 `i18n_fallback.js`가 한국어 원문을 돌려줌)는
  코드로만 검증했고 브라우저에서 재현하지 않았다.
- 쿠키와 `Accept-Language`가 동시에 있을 때 쿠키가 우선한다는 것은 Django 보장이며 이 저장소
  테스트는 두 요인을 따로만 확인한다.
- 일본어·중국어 번역은 원어민 검수 전이다. 푸터 일본어 "アクティビティカレンダー"가 4열 안에서
  줄바꿈된다.
