# UI 다국어(ko/en/ja/zh-hans) — 기술 기록(트랙 43-1·43-2·43-3)

상태: **43-1은 PR #395로 머지됨(2026-10-21 13:02Z `[실측 gh]`). 43-2(이벤트 목록·달력·상세)는
구현됨(2026-10-22, 미머지, 브랜치 `feat/i18n-events-43-2`)** — 공개 셸·홈·계정(allauth)·공용 JS와
이벤트 화면의 UI 문구를 Django gettext로 옮겼다. 카테고리 이름 7개도 번역된다(사용자 결정 2026-10-22). 컬렉션·활동·마이페이지는 43-3이다.
이 문서는 **가드레일만** 담는다. 계획·결정 이력은 `prompt_plan.md` 트랙 43 절이 정본이다.

## Current fact

- 언어 결정은 **쿠키 → `Accept-Language` → `ko`** 순서이고 URL 접두사는 없다.
  `LocaleMiddleware`는 `SessionMiddleware`와 `CommonMiddleware` 사이에 있다
  (`config/settings.py:334`). `LANGUAGE_CODE="ko"`(403), `LANGUAGES`는 ko·en·ja·zh-hans
  4개(405), `LOCALE_PATHS=[BASE_DIR/"locale"]`(411), `i18n` 컨텍스트 프로세서(368).
- 언어 쿠키는 `Secure`(기존 `SECURE_COOKIES` 스위치)·`SameSite=Lax`·`HttpOnly`다
  (`config/settings.py:557-559`). 전환은 푸터 폼이 `/i18n/setlang/`에 POST한다
  (`config/urls.py:27`, Django 표준 뷰). JS 번역 사전은 `/jsi18n/`
  (`config/urls.py:26`)이 내려준다.
- 원문(msgid)은 **한국어**다. `ko`는 카탈로그가 없고 msgid가 그대로 나온다.
  카탈로그는 `locale/{en,ja,zh_Hans}/LC_MESSAGES/{django,djangojs}.po` 6개이며
  `.mo`는 커밋하지 않는다(`.gitignore`). 언어당 메시지는 django 643건 + djangojs
  69건이다 `[실측 msgfmt --statistics 2026-10-22, 43-3 반영 후]`(43-2 대비 새 항목 django 269 + djangojs 42 = 311 `[계산]`).
- 스태프 화면은 쿠키 언어와 무관하게 항상 한국어다. Django 뷰는
  `staff_console_required`(`staff/permissions.py:25`), DRF 뷰는 `staff_api_korean`
  (`staff/permissions.py:31-46`, `staff/urls.py`·`staff/api_urls.py`의 DRF 라우트 12개
  전부)가 `translation.override("ko")`로 감싼다. 스태프 셸은 카탈로그 없이
  `i18n_fallback.js`만 로드한다(`templates/staff/base_staff.html:81`).
- 인증이 필요한 API의 403 본문에는 언어 무관 `code: "not_authenticated"`가 실린다
  (`core/api_exceptions.py`, `config/settings.py:618`). 프론트는 `detail` 문구를 비교하지
  않고 이 `code`로 로그인 안내를 띄운다(`static/js/shared/api.js`).

## Decision

- **쿠키 방식, URL 접두사 없음**: `i18n_patterns`를 접두사 없는 기본 언어로 쓰면
  접두사 없는 `/api/` 요청이 `LANGUAGE_CODE`로 강제되고(`django/middleware/locale.py`),
  접두사를 붙이면 한국어 URL 전체와 테스트 리터럴 URL이 바뀐다. 외국어 SEO·hreflang은
  이연이다.
- **번역 호출은 문구가 적힌 자리에서 감싼다**: 모듈·클래스 수준(폼 라벨, `core/vocab.py`
  라벨)은 `gettext_lazy`, 요청 처리 함수 안은 `gettext`. 문구를 한 층으로 끌어모으지 않는다.
- **행사 콘텐츠·사용자 입력은 번역하지 않고, 카테고리 이름은 번역한다.** 행사 콘텐츠(제목·작품명·
  장소·요약·출처 이름)와 사용자 입력은 `lang="ko"`로 표시한다. 지역 라벨 `REGION`은 필터 어휘라
  번역한다. 카테고리 이름도 번역한다(사용자 결정 2026-10-22): 어휘 7개는 지연 번역이고, DB 라벨은
  뷰에서 `gettext(label)`로 어휘 msgid와 같은 글자만 번역된다. 스태프가 새로 만든 번역 없는 라벨은
  한국어 그대로 두고 조건부 `lang="ko"`를 붙인다(가드레일 16).
- **번역 검수는 사람이 아니라 독립 AI 검수자가 한다**(사용자 지시 2026-10-21, 이전의
  "일본어·중국어는 사용자가 검수 시트를 확인한 뒤 production" 조건을 대체). 번역가와
  별개인 에이전트가 언어별로 전체 카탈로그를 읽고, 구조(자리표시자·태그·개행·`%`)가
  현재 번역과 같은 제안만 반영한다. production 조건은 아래 "AI 검수 기록"과 카탈로그
  가드 통과다(`docs/deploy-runbook.md` §3-18). 원어민 사람 검수는 하지 않았다.

## Guardrail

1. **`compilemessages`는 반드시 `--ignore .venv`.** 이 명령은 `./locale`만 보지 않고
   현재 디렉터리 전체를 순회해 이름이 `locale`인 폴더를 전부 수집한다
   (`django/core/management/commands/compilemessages.py:85-100`). 설정 모듈을 줘도
   순회는 일어난다. 빼면 `.venv` 서드파티 `.po` 1280개를 다시 컴파일한다
   `[실측 로그 1282줄]`.
2. **`msgfmt --check-format`은 `javascript-format` 불일치를 잡지 못한다**(종료 코드 0,
   python-format만 종료 코드 1) `[실측 msgfmt 프로브]`. 그래서 번역문의 자리표시자·
   HTML 태그를 원문과 비교하는 테스트가 유일한 안전망이다
   (`tests/core/test_i18n_catalog_completeness.py`).
3. **번역문의 HTML 태그는 속성까지 글자 그대로 원문과 같아야 한다.** `blocktranslate`
   본문과 `mark_safe`(`accounts/forms.py` 약관 동의 라벨)는 msgstr을 HTML로 그대로 렌더한다.
   번역가가 `onmouseover` 같은 속성을 넣으면 XSS가 된다. 태그 **이름**만 비교하던 가드는
   속성 주입을 통과시켰다 `[실측 뮤테이션]`.
4. **지연 번역 객체는 `str`이 아니다.** `json.dumps`는 못 직렬화한다 — 지역 라벨이
   JSON-LD payload에 들어가는 간접 경로에서 터졌다(`web/views/events.py:540`,
   `DjangoJSONEncoder`로 해결). `str` 전용 API(`", ".join`, `json.dumps`, 정규식)에 라벨을
   넘기기 전에 소비처를 `rg`로 추적한다.
5. **언어에 따라 달라지는 문구를 서버 응답의 문자열로 비교하지 않는다.** DRF·Django 내장
   문구는 `LocaleMiddleware`가 켜지는 순간 활성 언어로 번역된다. 판별은 언어 무관 `code`로.
6. **서식 문자열에 한국어를 박지 않는다.** `date:"n월 j일"`은 외국어 화면에 한국어를 섞는다.
   `DATE_FORMAT`·`MONTH_DAY_FORMAT`과 월 이름 `F`를 쓴다(한국어 출력은 글자 단위로 같다).
   `tests/core/test_ui_korean_literal_guard.py`가 템플릿·JS의 번역 태그/`gettext` 밖 한국어를
   막는다. **이 가드는 승인 범위 파일 목록을 직접 가지고 있다.** 43-2에서 이벤트 템플릿 3개와
   `static/js/pages/event_list.js`를 더해 템플릿 45개·JS 15개가 됐다
   `[코드 tests/core/test_ui_korean_literal_guard.py]`. `web/views/events.py`에는 번역 호출 밖
   한국어 문자열 상수가 없음을 AST로 막는 가드가 따로 있다(다른 파이썬 파일은 아직 가드가 없다).
   43-3에서 범위를 넓힐 때 목록과 기대 개수를 함께 갱신한다.
7. **500 페이지는 컨텍스트 프로세서 없이 렌더된다.** `<html lang>`은 변수가 아니라
   `{% get_current_language %}` 태그로 얻고(`templates/base.html:1`), 404·429·500 템플릿에는
   변수 보간 `blocktranslate`를 쓰지 않는다. 전환기는 `{% if request %}` 안에서만 렌더한다.
8. **언어 전환기의 언어명은 자기 표기다.** `{% get_available_languages %}`는 이름에 `gettext`를
   적용해 한국어 화면에서 English가 "영어"로 나온다. `get_language_info_list`의
   `name_local`을 쓴다(`templates/core/partials/_site_footer.html:60`).
9. **스태프 DRF 라우트를 추가하면 `staff_api_korean`으로 감싼다.**
   `tests/staff/test_staff_api_language.py`의 전수 가드가 12개를 센다 — 라우트가 늘면 숫자와
   함께 갱신한다. DRF 응답 렌더는 뷰 반환 뒤로 미뤄지므로 데코레이터가 같은 구간에서 렌더까지
   끝낸다.
10. **`set_language`는 허용 목록이 아니라 로케일 파일 존재로 쿠키를 정한다**
    (`django/views/i18n.py:60-62`). Django에 번역이 있는 미지원 언어(fr)도 쿠키는 설정되지만
    읽을 때 `LANGUAGES`에 없어 무시된다. 허용 목록은 `LANGUAGES` 하나다.
11. **요청자 언어에 따라 달라지는 `gettext` 결과**를 DB·로그·분석 이벤트·세션에 저장하지
    않는다(요청자 언어가 저장 데이터에 섞인다). 로거 메시지에 `gettext`를 쓰지 않는다
    (`tests/core/test_error_logging_policy.py`). **언어를 키로 명시 저장하는 콘텐츠 번역
    (`Event.text_translations`, 트랙 44-1 — 로컬 러너가 만든 값이고 요청자 언어와 무관)은
    별개 데이터이며 이 가드레일의 대상이 아니다.** 상세 가드레일은 아래 "행사 콘텐츠 번역
    (트랙 44-1)" 절.
12. e2e 브라우저가 영어 `Accept-Language`를 보내면 화면이 영어가 되어 한국어 선택자가
    깨진다. 이 환경의 Playwright Chromium은 헤더를 보내지 않아 ko로 렌더된다
    `[실측 2026-10-21, tests/e2e 10 passed]`. 환경이 바뀌면 컨텍스트 `locale`을 고정한다.
13. **같은 한국어 글자가 화면마다 다른 품사·역할이면 `msgctxt`로 가른다.** 영어는 상태 명사
    ("Saved")와 동작("Save")이 다르다. 통계 라벨·동작·날짜 접미에 문맥을 붙였다
    (`templates/core/partials/_home_collection_snapshot.html`). 문맥을 붙이기 전에 같은 msgid를
    쓰는 다른 곳을 `rg`로 센다. 상태 배지 `종료`는 다른 4곳이 쓰므로 문맥 없이 둔다.
14. **개수 바로 뒤에 붙는 단위·명사는 `ngettext`·`npgettext`로 복수형을 만든다.**
    `pgettext_lazy`는 개수를 받지 못해 영어에서 "1 items"가 된다
    (`web/views/account.py` `_build_delete_targets`). 한국어는 카탈로그가 없어 `msgid_plural`을
    같은 글자로 두면 출력이 변하지 않는다.
15. **속성 안 번역문은 이스케이프되지 않는다.** `{% translate "…" as v %}`와
    `{% blocktranslate asvar v %}`의 결과는 안전 문자열이라 `aria-label="{{ v }}"`에서도 그대로
    출력된다 `[코드 django/templatetags/i18n.py 94-98·201행 근처]`. 번역문에 원문에 없는 `"`가
    들어가면 속성이 깨지므로 카탈로그 가드(`tests/core/test_i18n_catalog_completeness.py`, msgstr의
    이스케이프되지 않은 `"` 개수가 원문 이하)가 유일한 안전 장치다. 변수 부분
    (`blocktranslate with label=…`)은 이스케이프된다. (43-2 초안이 "변수 출력은 이스케이프됨"이라고
    잘못 적었다가 BIR이 소스로 정정했다.)
16. **`lang="ko"`는 콘텐츠 요소에만 붙인다.** 행사 제목·작품명·장소·요약·출처
    이름(`source_name`)에 붙이고(카테고리 이름은 번역되므로 `lang`이 없다), 번역되는 어휘(`region_label`·`status_label`·`user_status_label`)에는
    붙이지 않는다. 번역문 안에 한국어 값이 끼면 값만 `<span lang="ko">%(x)s</span>`로 msgid 안에서
    감싼다(번역가가 어순을 바꿔도 한국어 값만 표시됨) — 예 `<span lang="ko">%(source)s</span> 제공`.
    이 msgid의 태그와 속성은 msgstr에 글자 그대로 있어야 한다(가드레일 3). 출처 이름은 처음에
    영문일 수 있다고 보고 `lang`을 빼려 했으나 출처가 있는 행사 50개의 값 5종이 전부 한글이어서
    `[실측 shell 2026-10-22]` 뒤집었다. 출처가 영문인 행사가 생기면 그 값에도 `ko`가 붙는다.
    번역 없는 DB 카테고리 라벨은 활성 언어가 `ko`가 아니고 `gettext(label) == label`이며 라벨에
    한글이 있을 때만 `lang="ko"`를 붙인다(영문 라벨에는 붙이지 않는다).
17. **같은 한글이 페이지 제목과 링크 문구로 다르게 읽히면 `msgctxt "페이지 제목"`으로 가른다.**
    푸터의 `이벤트 목록` 링크는 영어 "All events"인데 목록 페이지는 기본 필터가 진행·예정만 보여
    줘서 h1·`<title>`이 "All"이면 오해를 준다. h1·title·og:title은 `context "페이지 제목"`(영어
    "Events")을 쓴다.
18. **언어별로 길이가 달라지는 라벨이 같은 줄에 컨트롤과 놓이면 줄바꿈을 허용한다.** 이벤트 달력
    월 이동 줄은 영어 360px에서 12개월 중 6개월이 라벨과 컨트롤이 겹치고 최대 51px 넘쳤다
    `[실측 Chrome DevTools 2026-10-22]`. 데스크톱은
    `grid-template-columns: minmax(max-content, 1fr) auto 1fr`, 45rem 이하는 flex-wrap으로 바꿔 한
    줄에 안 들어가면 컨트롤이 아래 줄 오른쪽으로 내려간다(`static/css/pages/event_calendar.css`;
    영어 8개월은 줄 높이가 44px에서 94px가 된다 `[실측]`, 한국어는 변화 없음). 활동 달력의
    `.calendar-month-nav`(`static/css/pages/archive_calendar.css`)는 **세로 flex라 같은 위험이 없다** —
    열두 달 × 4개 언어 × 360·320px에서 겹침 0·가로 넘침 0·제목 1줄·nav 높이 78px가 한국어와 같다
    `[실측 Chrome DevTools 2026-10-22]`(43-3 계획의 "같은 위험" 추정은 틀렸고 실측으로 정정).
19. **지연 번역 라벨은 `str` 전용 API에 그대로 넘기지 않는다.** `core.vocab.CATEGORY_LABELS` 값이 지연 번역이라 `" · ".join`·`json.dumps`·`str.replace`는 `TypeError`다 — 메타 설명 폴백은 `str()`로 감싼다. 지연 객체는 `==`·`hash`·`+`·`{{ }}`에서는 동작한다 `[코드 django/utils/functional.py:121,151,160-163]`.
20. **저장값·필터 토큰·URL 키는 언어 무관한 원문으로 둔다.** 아카이브 방문 필터는 라벨 문자열이 `cat:<라벨>` 토큰이라(`web/views/archive.py`) 번역된 라벨을 쓰면 푸터 언어 전환이 쿼리를 보존하는데(`templates/core/partials/_site_footer.html:63`) 필터가 조용히 풀리고 개인 항목의 한국어 `팝업스토어`가 공식 칩과 갈라진다. 토큰은 `CATEGORY_SOURCE_LABELS`의 한국어 원문, 표시만 번역한다. `PERSONAL_ENTRY_CATEGORY_SUGGESTIONS`(칩을 눌러 입력창에 채우는 값, `core/vocab.py`)도 사용자 결정(2026-10-22)으로 번역 대상이다. 다만 번역된 문구를 그대로 저장하면 같은 원칙이 깨지므로 설계 기본값은 저장 시 서버가 번역 문구를 한국어 원문으로 되돌려 저장하는 정규화다 — 43-3에서 구현·검증한다(현재는 미구현, 칩은 한국어 그대로).
21. **테스트에서 요청 전에 지연 라벨을 평가하지 않는다.** `LocaleMiddleware`가 `translation.activate`만 하고 되돌리지 않아 직전 테스트의 언어를 읽는다 `[코드 django/middleware/locale.py:35]`. 기대값은 리터럴이나 요청 뒤 평가로 쓴다. 한국어 요청에서는 문서 루트가 `<html lang="ko">`라 "ko 범위가 아니다" 단언이 항상 거짓이므로 한국어 요청은 "명시적 `lang` 속성이 없다"로 단언한다.
22. **한국어 문자열 상수 가드는 디코딩된 값을 본다.** 한글 판별 정규식 `"[가-힣]"`나 `"가"` 이스케이프도 가드에 걸린다 — `web/views/events.py`는 코드포인트 정수 비교(`0xAC00 <= ord(ch) <= 0xD7A3`)를 쓴다. 번역 불가 DB 라벨 번역은 `gettext(label)`이라 우연히 다른 msgid와 같은 라벨(`기타`·`종료`·`전체` 등)이면 그 번역이 붙는다.

23. **저장값은 항상 한국어 원문, 표시만 요청 언어로 바꾼다 — 정규화는 시리얼라이저에서 한다.**
    개인 항목 카테고리(`PERSONAL_ENTRY_CATEGORY_SUGGESTIONS`)와 굿즈 유형(`COLLECTION_ITEM_TYPE`) 칩은
    번역된 문구를 입력창에 채우므로 번역 문구가 API로 들어온다. `core/vocab.py`의
    `normalize_personal_category`·`normalize_collection_item_type`이 어느 지원 언어의 번역이든
    한국어 원문으로 되돌리고(앞뒤 공백·대소문자·**라틴 문자 악센트만** 무시 — 일본어 탁점·반탁점을 접으면
    `ポ`가 `ホ`로 접혀 다른 글자가 같은 키가 된다), `archive/serializers.py`의 `validate_category`·
    `validate_item_type`이 호출한다. 개인 항목 쓰기 경로가 둘(POST는 서비스, PATCH는 서비스 없이 DRF 기본
    `update`)이라 서비스가 아니라 시리얼라이저에 둬야 둘을 한 곳에서 덮는다
    `[코드 archive/views.py:112-116,149-160]`. 표시는 `*_label` 함수와 템플릿 필터
    (`core/templatetags/vocab_labels.py`)가 **한국어 원문이 어휘일 때만** `gettext`한다 — 어휘 밖
    사용자 입력("종료" 등 우연히 다른 msgid와 같은 값)에는 쓰지 않는다(가드레일 22). 수정 화면은 저장된
    원문을 번역 라벨로 미리 채워야 칩 활성 비교(`dataset.categoryLabel === value`)가 맞는다. 방문 필터 토큰은
    저장값(한국어 원문)이고 칩 라벨만 번역한다(가드레일 20).
24. **함수 안에서 나는 사용자 메시지는 즉시 `gettext`, 영어 `detail`은 번역하지 않는다.** 서비스·시리얼라이저·
    뷰의 검증 메시지는 요청 안에서 문자열이 되므로 `gettext`(지연 아님)다. 영문 식별자(`quantity` 등)는 API
    필드명이라 msgid에 그대로 둔다. `archive/views.py`의 영어 `detail` 3곳은 `code`와 함께 내려가고 프론트가
    `code`를 먼저 처리해 화면에 나오지 않으므로(`static/js/shared/api.js:107-112`) 번역·통일하지 않는다 —
    `code`가 4개 언어에서 같고 `detail`이 영어 그대로임을 테스트가 고정한다.
25. **날짜·월 서식은 Django 로케일 서식을 쓰고 한국어 불변을 12개월로 확인한다.** `Y년 n월 j일`→`DATE_FORMAT`,
    `n월 j일`→`MONTH_DAY_FORMAT`, `Y년 n월`→`YEAR_MONTH_FORMAT`, 달력 제목 월→`F`, 좁은 월 칸(44px)→`M`
    (한국어 열두 달에서 `n월`과 글자가 같다 `[실측 django shell]`). 활동 달력 날짜 셀 aria-label은 `DATE_FORMAT`과
    요일을 자리표시자 `blocktranslate`로 합성한다(영어만 어순이 바뀐다). 숫자 서식(`Y/m/d`, `Y.m.d`)은 그대로 둔다.
26. **JS에서 변수가 낀 문장은 한 줄 단일 리터럴 `interpolate(gettext("…%(n)s…"), {n: …}, true)`로 쓴다.**
    `"…" + 변수 + "…"` 연결은 가드가 첫 리터럴만 벗기고 나머지를 위반으로 본다. 복수형이 필요한 곳(검색 결과 수,
    업로드 개수)은 `ngettext`이며 저장소 JS의 첫 사례다 — 한국어 단수·복수는 같은 글자라 폴백도 한국어 원문과
    같다(`static/js/shared/i18n_fallback.js`). `pgettext`는 JS에서 쓰지 않는다(폴백·가드 미지원). 이미 있는
    msgid(`네트워크 오류가 발생했습니다. 다시 시도해 주세요.` 등)는 공백·마침표까지 같은 글자로 재사용한다.

  zh-hans는 한자 필수·가나 금지; `_LATIN_RE`에서 ×·÷ 제외).
  - 숫자: 번역 쪽은 시각 분 표기 `:00`을 제거하고 선행 0을 뗀 토큰으로 "지어낸 숫자"
    (번역 집합 ⊆ 허용 집합)를 비교한다. 원문의 `N만/N천/N억`(소수·쉼표 뒤·연속 단위
    제외)은 확장값을 허용 집합에만 추가하며 보존 의무는 없다. "원문 4자리 이상 숫자
    보존"은 원형 토큰으로 비교한다.
  - `work_title`·`location_name`은 라틴 문자만 쓰인 경우 ja·zh-hans에서도 문자 판정을
    건너뛴다(`_PROPER_NOUN_FIELDS`, 고유명사 라틴 예외).

  - 표시: `select_display`는 해당 언어 엔트리의 4필드가 전부 문자열일 때만 번역을 채택한다.

### Decision

- 실행 주체는 사용자 맥의 러너다(서버 LLM 호출 불허, 2026-07-04 사용자 결정 계승).
- 건별 사람 검수는 없다(사용자 결정 "건별 사람 검수 배제"). 방어선은 토큰 비밀·자동
  검증·격리 로그·44-2의 "AI 번역" 표시다.
- `manual`은 이벤트 단위 플래그 하나다. 언어별로 쪼갤지는 44-3 착수 때 사용자 재확인한다.
- `report_translation_queue`는 `--dry-run` 같은 인자가 없는 읽기 전용 보고 명령이다 — 쓰기
  모드가 없다.
- 고유명사 라틴 예외는 실기동에서 `SPY×FAMILY`와 `Starfield Hanam`이 오탐으로 격리된 것을
  근거로 추가됐다.

### Known gap

- 의미 충실성은 자동 검증 불가하다 — 토큰이 유출되면 숫자·태그가 없는 임의 문장이 통과한다.
- 간체와 번체는 문자 블록으로 구분할 수 없어 프롬프트 지시에만 맡긴다.
- "5만원"→"KRW 50,000" 같은 단위 풀어쓰기는 지어낸 숫자로 격리된다.
- 격리 언어는 44-3 전까지 영구 `null`이고 가시성은 로그와 `report_translation_queue`
  집계뿐이다.
- 서버 큐가 가장 오래된 20건만 돌려주므로, 시도 한도에 도달한 이벤트가 20건을 넘으면 그보다
  새 이벤트가 처리되지 않을 수 있다.
- 큐는 게시 이벤트를 파이썬으로 훑는다(`Event.objects.published().only(...).iterator()`).
  규모가 커지면 SQL로 전환한다.
- `transaction.atomic()` 제거는 테스트가 구분하지 못한다(도메인 테스트가 이미 트랜잭션 안에서
  돈다).
- 번역 의미 품질의 사람 검수·수작업 표본 평가는 하지 않았다(사용자 결정: AI 검증만).
- 러너 토큰은 단일 공유 비밀이다(읽기·쓰기 분리 없음, 기존 `DRAFT_DISCOVERY_RUNNER_TOKEN`과
  같은 토큰을 공유).
- **문자 판정·ASCII 우회·한글 잔존 검사는 NFKC로 접은 문자열에서 돌고 저장은 NFC라서**,
  수학 알파뉴메릭 기호(예: U+1D400 대역) 같은 장식 유니코드가 판정은 통과하고 원형 그대로
  저장될 수 있다 — XSS가 아니라 표시 품질·눈속임 문제이며 44-2 착수 전에 정규화 통일
  여부를 확인한다.
- **러너 배치는 4xx(429 제외)·`AdapterOutputError`·`ValueError`만 이벤트별 시도 횟수에
  반영한다**(`local_runner/translation_flow.py::translate_pending_batch`). 5xx·429와
  `OSError` 등 통신·기타 예외는 전파되어 배치가 중단되고 횟수는 오르지 않으므로, 개별
  이벤트 탓인 `OSError`가 나면 그 배치가 매번 같은 자리에서 중단될 수 있다. 트리거: 실제
  발생 시.
- **번역 중 새 탐색 claim이 최대 약 720초 늦어진다**(3건×2회×120초 `[계산]`, 평시 약 31초
  `[계산]`). 첫 백필 중 특히 두드러진다.
- **고유명사 라틴 예외의 최대 폭은 `min(400, max(40, 6 × 원문 길이))`자**
  `[계산, 절대·상대 길이 검사 두 조건을 모두 통과해야 하는 코드 로직에서 도출 — 코드
  events/content_translation.py]`이다. 더 좁히려면(예: 80자) 제품 결정 재확인이 필요하다.
- **정상 규칙을 통과했지만 의미가 왜곡된 번역이 먼저 저장되면 `already_current` 때문에
  같은 해시의 정식 재제출이 덮어쓰지 못한다** — 복구는 `docs/operations-runbook.md`의
  재큐잉 절차(44-3의 "다시 번역" 전까지).
