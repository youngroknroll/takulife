# 계약 가드가 무엇을 잡고 무엇을 못 잡는가

2026-07-30 전수 검수에서 가드 네 개가 **통과하면서 아무것도 지키지 못하는**
상태가 실측으로 드러났다(PR #251·#253). 이 문서는 고친 뒤의 실제 능력과
남은 한계를 적는다. 가드를 손대기 전에 읽어라.

## `tests/core/test_architecture_boundaries.py` — 도메인 경계

**잡는다**: 등록된 14개 모듈의 정적 import,
`importlib.import_module("문자열")`, `__import__("문자열")`.

**못 잡는다**: 목록에 없는 모듈, 비-리터럴 인자(변수·f-string),
`from importlib import import_module` 후 이름 직접 호출, import 없는 행위적 결합(시그널 등).

**실측 이력**: 확장 전에는 `events/queries.py`에 금지 임포트를 넣어도,
`drafts/views.py`에 `importlib`를 써도 **2013건이 전부 통과**했다.
누락 모듈 5개(`events/models.py`·`events/queries.py`·`drafts/models.py`·
`drafts/serializers.py`·`drafts/queries.py`)를 등록하고 `ast.Call` 순회를 추가해 닫았다.
각 모듈마다 금지 임포트를 넣어 **담당 케이스 하나만 Red**가 되는 것을 왕복 확인했다.

⚠️ `core/views`가 패키지가 되면서 이 파일의 스캔이 **경로 하드코딩에서 패키지
순회로 바뀌었다.** 파일이 0개면 공허 통과하므로 최소 1개 단언도 함께 있다.
`core/views/` 아래 새 모듈이 생겨도 이 테스트는 고칠 필요가 없다.

## `tests/core/test_service_signature_conventions.py` — 키워드 전용 인자

**지키는 것**: *다른 앱이 가로질러 호출하는* 서비스 경계 5개
(`events`·`archive`·`drafts`·`staff`·`core.promotion`).

⚠️ **`accounts.services`를 목록에 추가하지 마라.** 추가하면 4개 함수가 즉시
빨개지지만 **위반이 아니다** — 호출처가 전부 `accounts` 앱 내부다
(`views.py`, `signals.py` 2곳, purge 커맨드). 이 가드가 방어하는 경계가 아니다.
넣고 고치면 호출처 약 20곳을 바꾸는 헛일이 된다. 제외 근거는 그 파일 독스트링에도 있다.

**실제 누락은 `core.analytics`다.** `events/views.py`·`staff/views/__init__.py`·
`archive/services.py`가 임포트하는 진짜 교차 도메인 서비스인데 목록에 없고,
공개 함수 4개가 위치 인자를 받는다. **미착수** — `record_event` 호출처만
프로덕션 15곳 이상이라 별도 승인이 필요하다. 위치 인자가 의도된 설계라는 근거는
코드·문서 어디에도 없어 드리프트로 판단하지만 원 설계 의사는 **미확인**이다.

## `tests/core/test_error_logging_policy.py` — 예외·로깅

**못 잡는 것**: `# except-ok: <이유>` 마커의 **정당성**. 핸들러 범위 안에 그 한 줄만
있으면 로깅도 재발생도 없이 통과한다. 마커를 새로 쓸 때는 리뷰에서 사람이 판단해야 한다.
마이그레이션 파일은 스캔 대상 밖이다.

## 마크업 리터럴 단언 — 리네임 취약성

**`not in` 형태만 위험하다.** `in` 형태는 리네임하면 즉시 시끄럽게 실패한다.

실측: `class=` 단언 37개 중 `not in`은 8개였고, 그중 **실제로 회귀를 놓친 것은 1개**
(컬렉션 빈 상태), **이미 공허한 것 2개**(저장소에 없는 문자열),
나머지 5개는 양성 단언·`aria-label`·앵커 개수 가드가 짝을 이뤄 안전했다.

**새로 쓸 때의 규칙**: "없음"을 단언하려면 **스타일 클래스가 아니라 안정 앵커**를
써라 — 접근 이름(`aria-label`), `href`, 폼 필드명. 클래스 리터럴은 리네임 한 번에
"존재하지 않는 문자열의 부재"를 검사하게 된다.

⚠️ **앵커 유일성은 페이지 단일 템플릿에서 세지 마라.** 렌더 결과는 `base.html`과
partial이 합쳐진 것이다. `<form`을 앵커로 골랐다가 `_topbar.html`의 로그아웃 폼
때문에 실패한 사례가 있다.

## 이 저장소에서 반복되는 실패 유형

- **기대값이 전부 0인 단언은 무방비다.** 새 dict 키를 상수 `0`으로 박아도
  519건이 통과한 사례가 있다(이벤트 카탈로그 트랙).
- **통과는 증거가 아니다.** 가드를 고쳤으면 **깨뜨려서 Red가 되는지**와
  **깨끗한 상태에서 Green인지**를 **둘 다** 재라. 한쪽만 재서 잘못된 앵커가
  통과한 사고가 있었다.
- **뮤테이션 판정은 종료 코드로만 하라.** stdout에서 `failed`를 문자열로 찾으면
  AXES 로그의 "failed login attempts"를 테스트 실패로 오독한다.
- **동시 실행 간섭**: 사용자가 같은 저장소에서 작업 중이면 pytest가 겹쳐
  전체 스위트가 거짓 에러를 낸다(3 errors → 재실행 시 정상). 단발 실패를
  결함으로 보고하기 전에 재실행하라.
