# API Foundation Work Log

Date: 2026-05-20

## Scope

This work created the first backend foundation for OshiLog as a RESTful API project.

Included:

- uv project setup.
- Django project scaffold.
- Django REST Framework setup.
- Core API endpoints.
- Bootstrap tests.
- `.env` based `SECRET_KEY` loading.
- Project status documentation.

Not included:

- Event domain model.
- EventDraft domain model.
- URL extraction.
- Admin approval workflow.
- Authentication policy.
- PostgreSQL deployment settings.

## Risks And Notes

- The project is not initialized as a git repository yet.
- Local `.venv`, `.pytest_cache`, and `__pycache__` directories were generated by verification commands and are ignored.
- `SECRET_KEY` has a local fallback only for bootstrap convenience. Real secrets should be placed in `.env` or deployment environment variables.
- The earlier foundation plan is superseded by the REST API backend plan.

## Deferred Refactoring Note

- Topic: Split Django settings by environment.
- Why it is not part of the current scope: The current task only bootstraps local REST API development.
- Why it may be needed later: Production deployment needs stricter `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, database, logging, and secret handling.
- Trigger condition: Before Render deployment, PostgreSQL integration, or public hosting.
- Expected change location: `config/settings.py` or `config/settings/`.
- Related tests: `uv run python manage.py check`, `uv run pytest -q`.
